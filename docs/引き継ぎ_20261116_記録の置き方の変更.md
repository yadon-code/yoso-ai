# 引き継ぎ（2026-11-16〜17）：記録の置き方を変えました

この置き場で作業する AI（クラウドの Claude など）向けのメモです。**作業を始める前に `git pull` してください。** 2026-11-16 に、毎日の自動予想の「記録の置き方」を作り直しました。予想の計算・買い目の判定・学習・Discord の文面は変えていません。

## 何が変わったか

1. **予想・エア投票・オッズの記録は、main にそのまま置かなくなりました。**
   - 置き場は `data/vault/`（日ごとの束 `YYYYMMDD.bin`・`common.bin`・`index.json`）。合言葉（Secret `SITE_PASSWORD`）で暗号化してあります。
   - 中身を開くには `src/records.py` の仕組みが必要です（後述）。生の CSV で読みたいときは `data/cache/records/` に戻した写しがあります（GitHub Actions の中だけ）。
   - 理由：この置き場は公開なので、記録をそのまま置くと誰でも読めてしまうため。
2. **10分ごとの保存は、`site-data` という別のブランチへ**。
   - `data/site/*.enc` と金庫の最新を、**いつも1コミットだけ**で上書きします（force-with-lease）。履歴を積まないので置き場が太りません。
   - `web/index.html` は `site-data` を読み、無ければ `main` を読みます。
3. **新しいファイル `src/records.py`**：金庫を作る・読む・戻す・守る（記録が減らないか確かめる）。回の始めに `python src/records.py restore`、保存は `scripts/push_data.sh` から `records.py save`。
4. **`src/sitecrypt.py`**：同じ中身なら同じ暗号文になる形に（塩は固定、nonce は鍵＋ファイル名＋中身から）。ファイルの形と `web/index.html` の復号手順は前と同じ。前の形のファイルも読めます。
5. **実行ログに買い目の中身を出さない**（合言葉があるとき）。「予想しました（v2・買い目 N点）」などに。
6. **`live.yml` の手順**：記録を戻す手順（`id: records`）が成功した回だけ記録を保存、展開（`id: data_ready`）が成功した回だけ過去データを保存。`RECORDS_MODE: vault` を `legacy` にすると前の形に戻せます。
7. **main への保存のしかた**：`git pull --rebase` をやめて、GitHub の main の最新を土台に、作業フォルダと index に触らずにコミットを組み立てて送る形に（`records.py`）。動いている回が途中で main の新しいコードを拾うことはもうありません。

- **`data/predictions/`・`data/paper/`・`data/odds_pre/`・`data/site/` は main にありません。** 古い記事やメモに「ここにある」と書いてあっても、今は違います。

- **戻し方を間違えると記録が消えます。** 新しいしくみの回が1回でも始まったあとに、いきなり revert しないこと。手順は README の「戻すとき」。
